# Releasing, deploying and verifying

For maintainers. Resolve ships through three channels that move independently:

| Channel | What | How it ships | Who can ship |
| --- | --- | --- | --- |
| Website and dashboard | `apps/web` | AWS Amplify builds every push to `main` | Anyone who can push to `main` |
| Backend and infrastructure | `services/*`, `infrastructure/terraform` | "Deploy prod" GitHub workflow (manual, owner approval) | Owner approval |
| Browser extension | `apps/extension` | GitHub Release with a zip; the website's Download page links the latest | Maintainer with `gh` release rights |

There is no browser-store channel yet (see [ROADMAP.md](ROADMAP.md#browsers-and-distribution)).
Version history: [CHANGELOG.md](../CHANGELOG.md).

## Production

| Item | Value |
| --- | --- |
| AWS account | Dedicated production account in the owner's organisation, `ap-southeast-1` |
| Website | https://getresolved.site (Amplify custom domain; `www` and the Amplify address redirect) |
| Email | SES production access; sender "Resolve" &lt;no-reply@getresolved.site&gt; with DKIM, SPF, DMARC, custom MAIL FROM; bounce and complaint suppression |
| DNS | Route 53 hosted zone with DNSSEC (DS record at the registrar) and query logging |
| Extension | Built with production settings and the fixed beta key, so its ID (`jlgcfgmonpplhjanafoghpebgjnplbkc`) matches the registered sign-in callback |

## Release the extension

Versions follow semver in `apps/extension/package.json` (the manifest takes its version from it).
Tags are `vX.Y.Z`; the release asset is `resolve-X.Y.Z-chrome.zip` (the Download page picks the
first `.zip` whose name contains "chrom").

1. Bump `apps/extension/package.json` and add the version to [CHANGELOG.md](../CHANGELOG.md).
2. Run the checks below; commit and push to `main`; wait for CI to pass.
3. Build the release zip with production settings (needs `apps/extension/.env.production.local`,
   generated by `SITE_URL=https://getresolved.site pnpm extension:env prod`):

   ```bash
   pnpm --filter @resolve/extension zip:beta
   cp apps/extension/.output/resolveextension-X.Y.Z-chrome-beta.zip resolve-X.Y.Z-chrome.zip
   ```

   Spot-check the zip: version, `"key"` present, production dashboard URL in `background.js`,
   `NOTICE.txt` and `models/nsfw/NOTICE.txt` included, every script starts with the ownership banner.
4. Publish, targeting the full commit SHA:

   ```bash
   gh release create vX.Y.Z resolve-X.Y.Z-chrome.zip --target <full sha> \
     --title "Resolve X.Y.Z" --notes-file notes.md --latest
   ```

   Release notes follow the earlier releases: what's new, Install or update (download, unzip into
   a folder you keep, Developer mode, Load unpacked; to update, replace the folder's files and
   reload), Known limitations.
5. The Download page caches the latest release for up to an hour. To show it at once, redeploy the
   website: `aws amplify start-job --app-id <app id> --branch-name main --job-type RELEASE`.

## Deploy the website

Push to `main`. Amplify builds and deploys; follow the job with
`aws amplify list-jobs --app-id <app id> --branch-name main --max-items 1`. CI runs separately on
the same push.

## Deploy the backend

1. Build the Lambdas: `pnpm --filter @resolve/api --filter @resolve/notifications build`.
2. Plan against production and review it (no unexpected destroys). Terraform cannot read
   `aws login` sessions; export temporary credentials first:

   ```bash
   eval "$(aws configure export-credentials --profile resolve-prod --format env)"
   terraform -chdir=infrastructure/terraform/environments/prod plan
   ```

3. Apply with the **Deploy prod** workflow (Actions → Deploy prod → Run workflow on `main`); the
   `prod` environment requires the owner's approval.

## Release checklist

Run before each release. Items marked ★ are [MASTER_PLAN.md](MASTER_PLAN.md) §14.5 acceptance gates.

**Code and tests**

- [ ] `main` is green in CI: lint, types, unit tests, build, E2E, Terraform validate, Checkov, `pnpm audit`
- [ ] `pnpm check` and production builds pass locally; `pnpm integration` passes against dev
- [ ] Extension E2E passes in Chromium, Edge and Brave (`RESOLVE_E2E_BROWSER=msedge|brave`)
- [ ] ★ AI privacy: zero-upload check (media filter E2E); no new network calls in the extension
- [ ] ★ Domain precedence: essential services reachable under a broad block
- [ ] ★ Member write and secrecy; ★ admin-only removal; ★ sharing modes and consent
- [ ] ★ Alert A: one generic email for a deliberate visit, none for redirects, pop-ups or restores
- [ ] ★ Alert B: departure email after leaving and after removal
- [ ] ★ Delivery: no duplicates, consent re-checked, DLQ alarm tested once

**Privacy and security**

- [ ] [qa/DATA_INVENTORY.md](qa/DATA_INVENTORY.md) matches the code; privacy policy updated from it
- [ ] New log lines use allowlisted fields only (`privacy.test.ts` passes)
- [ ] Built manifest permissions are exactly `identity`, `declarativeNetRequest`, `alarms`,
      `scripting`, `offscreen`; host access to the API and Cognito only; optional `<all_urls>` and
      `webNavigation`
- [ ] No secrets in the repo or bundles; [qa/THREAT_MODEL.md](qa/THREAT_MODEL.md) reviewed

**Infrastructure**

- [ ] Terraform plan reviewed; SES, alarms (SNS), budget, PITR and state versioning in place

**After release**

- [ ] Install the published zip in a clean browser profile: version, first run, sign-in window,
      Focus Mode start and block page
- [ ] Website Download page, Tutorial and README point at the new release
- [ ] Watch alarms and delivery metrics for 48 hours; record the release in [PROGRESS.md](PROGRESS.md)

Operational alarms and recovery: [qa/RUNBOOKS.md](qa/RUNBOOKS.md).
